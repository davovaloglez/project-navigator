## Why this matters

The CS360 data source is a ~44MB JSON export. Two endpoints serve it, and both do avoidable work on
every request:
- `GET /api/cs360/clientes` recomputes `calculateBaseScore(c)` for **all** ~461 clients on every
  request, even though the raw data is cached for 5 min and the score is deterministic per client.
- `GET /api/cs360/clientes/[id]` loads the **entire** in-memory dataset and `.find()`s one client to
  return — fine functionally, but it means the whole 44MB graph must be resident.

On Amplify (serverless), this drives cold-start latency and per-request CPU. Caching the derived list
and the per-client scores removes the repeated heavy computation. This is a contained optimization on
an admin-only, low-traffic surface — hence P3 — but it's a clear, low-risk win.

## Current state

`src/pages/api/cs360/clientes.ts` (verified at `34cffdc`):
```ts
export const GET: APIRoute = async () => {
  const { data, source } = await getCs360Clientes();
  const resumen: CsClienteResumen[] = data.map((c) => toClienteResumen(c, calculateBaseScore(c)));
  return new Response(JSON.stringify(resumen), { headers: { ..., 'X-CS360-Source': source } });
};
```
`getCs360Clientes()` (in `src/lib/cs360Data.ts`) caches the RAW adapted data for 5 min (read the file
to confirm the exact cache shape and TTL). But the `.map(... calculateBaseScore ...)` projection runs
on EVERY request — it is not cached.

`src/pages/api/cs360/clientes/[id].ts`:
```ts
export const GET: APIRoute = async ({ params }) => {
  const { data, source } = await getCs360Clientes();
  const cliente = data.find((c) => c.id === params.id);
  if (!cliente) return 404;
  return new Response(JSON.stringify(cliente), { ... });
};
```

`calculateBaseScore` lives in `src/utils/cs360.ts` (it iterates a client's tickets/activities/calls —
read it to gauge cost).

## Steps

### Step 1: Cache the derived resumen list

In `cs360Data.ts`, add a derived cache keyed to the same lifecycle as the raw cache (i.e. recompute
the resumen list only when the raw data is (re)loaded, not per request). Expose e.g.
`getCs360Resumen(): Promise<{ data: CsClienteResumen[]; source: string }>` that computes
`data.map((c) => toClienteResumen(c, calculateBaseScore(c)))` once per raw-cache refresh and memoizes
it. Invalidate it whenever the raw cache refreshes.

Update `clientes.ts` to call `getCs360Resumen()` instead of mapping inline.

**Verify**: `npx astro check` → 0; loading `/api/cs360/clientes` twice returns identical output (the
projection must be byte-identical to before — same scores, same `X-CS360-Source`).

### Step 2: Index the detail lookup

Add a memoized `Map<string, CsCliente>` built once per raw-cache refresh, and expose
`getCs360ClienteById(id)` that does a `Map.get` instead of `.find()`. Update `clientes/[id].ts` to use
it. Preserve the 404 behavior and headers exactly.

**Verify**: `npx astro check` → 0; `/api/cs360/clientes/<known-id>` returns the same client as before;
a bogus id still 404s with `{ error, code: 'NOT_FOUND' }`.

### Step 3: Manual render check

`npm run dev`, open CS360 dashboard (list + score distribution) and one client detail. Confirm scores
and content are unchanged from before the refactor.

### Step 4: Full verification

**Verify**: `npm test` → all pass; `npx astro check` → 0; `npm run build` → 0.
